# Quik

[中文](README.md) · [English](README.en.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · [日本語](README.ja.md)

メニューバーに常駐する macOS の重さ監視ツールです。今システムが重いのか、何が原因なのかの二つに答えます。

ネイティブ Swift で、外部依存はありません。定常状態の実測コストは 1 コアの 0.8%（12 コア換算で 0.07%）、常駐メモリは約 25 MB です。測定方法は `docs/metric-validation.md` にあります。表示言語はシステムに従い、簡体中国語・English・Deutsch・Français・日本語に対応しています。

## インストール

[Releases](https://github.com/lesliechowsh/quik/releases/latest) から `Quik-<version>.dmg` をダウンロードし、開いて Quik を Applications にドラッグします。macOS 14 以降が必要で、Apple Silicon と Intel の両方に対応します。

公開版は Developer ID で署名し、Apple の公証を受けています。初回起動時にセキュリティ警告は出ません。ソースからビルドしたものは ad-hoc 署名で、初回起動時に「システム設定 > プライバシーとセキュリティ」で「このまま開く」が必要です。

公開するときは `QUIK_SIGN_IDENTITY` と `QUIK_NOTARY_PROFILE` を設定します。`scripts/package.sh` が署名、公証、ステープルまで行います。

## ビルドと実行

Xcode 26 と `xcodegen` が必要です。

```bash
brew install xcodegen
scripts/build.sh
scripts/run.sh
```

`scripts/run.sh` を実行すると、画面右上にフローティングウィンドウが現れます。スコア、状態、最有力の原因プロセスを表示します。クリックするとパネルが開き、フローティングウィンドウの下に展開します。モードを切り替えても下方向にしか伸びません。ドラッグで移動でき、位置は記憶されます。このウィンドウはアプリをアクティブにせず、フォーカスも奪わず、すべてのデスクトップスペースで表示されます。

フローティングウィンドウを右クリックするか、パネル右下の「隐藏悬浮窗」（フローティングウィンドウを隠す）を押すとしまいます。選択は `hudVisible` 設定に保存され、再起動後も有効です。戻すときはパネルのボタン、またはメニューバーの項目を右クリックして「显示悬浮窗」（フローティングウィンドウを表示）にチェックを入れます。

Dock のアイコンにも状態が反映されます。通常モードでは状態と最有力の原因プロセスの名前を表示し、重いときはオレンジや赤になります。詳細モードではスコアを上半分に、状態ラベルをそのすぐ下に置きます。文字サイズは桁数に合わせ、2 桁は 70 ポイント、3 桁は 52 ポイントにして、「100」が「1…」に切り詰められず全体が表示されるようにしています。Dock のアイコンをクリックするとパネルが開きます。

メニューバーにも項目が現れます。

- `● 12` 緑または無色。システムはスムーズです。
- `▲ Slack Helper 44%` オレンジ。やや重い状態で、後ろは最有力の原因プロセスと 1 コアに対する割合です。
- `■ Slack Helper 44%` 赤。システムが止まっています。

メニューバーの空きが足りないと、macOS は項目をアプリメニューの下に押し込みます。フローティングウィンドウは影響を受けないため、常時表示の手がかりはこちらが担います。項目またはフローティングウィンドウをクリックするとパネルが開きます。パネルには重さのスコア、原因の内訳（CPU、メモリ、ディスク、応答遅延、温度）、上位 5 件の原因プロセス、それぞれに実行できる操作（3 秒間のサンプリング、アクティビティモニタを開く、終了）が表示されます。

既定は通常モードで、三つのことに答えます。今重いのか、誰が原因か、終了させるべきか。スコア、原因の詳細、履歴グラフ、サンプリングの入口は「詳細モード」の内側にあり、パネル右下で切り替えます。

原因プロセスは実行ファイル名ではなくアプリとして表示されます。`Slack Helper (Renderer)` は「Slack · 页面渲染」（ページ描画）として表示され、Dock とフローティングウィンドウで同じ名前を使います。アプリに属さないコマンドラインプロセスは作業ディレクトリで区別し、たとえば「node · my-project フォルダで実行中」と表示します。Slack を終了すると Slack 本体を終了し、ヘルパープロセスではありません。

`sample` のレポートは一時ディレクトリに書き出され、自動で開きます。3 秒間のコールスタックが入っており、プロセスがどの関数で止まっているか分かります。この入口は詳細モードにだけ現れます。

## AI アシスタント

インストール後は AI アシスタント（Claude Code、Codex、Cursor など）も「今マシンが重いのか」に答えられます。インストールするかどうかはあなたが決めます。通常モードのパネル下部で「安装到 AI 助手」を押し、開いたページで「安装」を押します。Quik は Agent Skills オープン標準（スキルは SKILL.md 入りフォルダ一つで、対応アシスタントが起動時に自動で見つけます）に従い、監視スキルを二つの標準スキルディレクトリに書き込みます：`~/.agents/skills/quik`（Codex、Cursor、Cline、Zed、Warp などが読む）と `~/.claude/skills/quik`（Claude Code が読む）、加えてコマンドラインツールを `~/.local/bin/quik` に。インストールするまで、Quik はホームディレクトリに何も書きません。スキルが参照するのはこの固定位置だけで、マシンのパスは一切含まれません。一度インストールすれば、Quik の更新でスキルとコマンドが自動的に新しくなり、再インストールは不要です。同じページの「移除」で両方を削除でき、Quik はそのまま動きます。

コマンドラインツールは `quik` で人が読める要約を、`quik --json` で機械可読な JSON を出力し、終了コードが状態を表します。0 は軽快、1 はやや重い、2 は停止中、3 はデータなし。アプリは毎秒 `~/Library/Application Support/Quik/status.json` をアトミックに上書きし、実測 516 バイトです。終了時に削除され、5 秒より古いデータは期限切れとして扱われます。スキルファイルは、完成された要約を引用し、top やサンプリングを自分でやり直さないようアシスタントに教えます。アンインストールでファイル探しは不要です。メニューバーのアイコンを右クリックして「卸载 Quik」を選ぶと、二つのスキルディレクトリの quik スキル、`~/.local/bin/quik`、`~/Library/Application Support/Quik` を一度に削除して終了します。その後アプリをゴミ箱へ。macOS はアプリ削除後にコードを実行しないため、後始末はアプリが生きているうちに行います。スキルファイルに同じ手順が書かれているので、どのアシスタントに「Quik をアンインストールして」と頼んでもきれいに消せます。

## 検証

```bash
# ユニットテスト: 判定、ヒステリシス、ランキング、表示の安定性
xcodebuild -project Quik.xcodeproj -scheme Quik -configuration Debug -derivedDataPath build test

# UI ループ: 固定の状態を注入し、実際のパネルを撮影して画面内にあることと空白でないことを検証
scripts/ui-check.sh

# 計測ループ: 制御した CPU 過負荷で、プローブと判定を検証
# 揺れの計測: 6 秒の全力負荷と 6 秒のアイドルを繰り返し、状態とランキングの変化回数を数える（scripts/flap-check.sh）
scripts/verify-experience.sh

# 言語: 表示言語ごとに実際のアプリを一度起動し、パネルとインストール画面の文字が端に寄っていないことを検証
scripts/verify-languages.sh
```

```bash
# フローティングウィンドウのループ: 再起動後も非表示または表示を保ち、実行中にしまって戻せる
scripts/verify-hud.sh

# 終了操作のループ: 実際のプロセスにシグナルを送り、終了することを確かめる
scripts/verify-quit.sh
```

```bash
# パッケージのループ: DMG をマウントし、アーキテクチャ、署名、ドラッグ先を検査して一度起動する
scripts/verify-package.sh

# エージェントのループ: 通常起動では何も書かないこと、明示的な導入と削除、CLI の両出力、期限切れ、終了時の後始末
scripts/verify-agent.sh
```

メンテナ向けの公開手順は `docs/distribution.md` にあります。

`scripts/ui-check.sh` はスクリーンショットを `/tmp/quik-ui` に出力し、三つを検証します。パネルとフローティングウィンドウの矩形が画面内にあること、各キャプチャが単色の空白ではなく複数の色を描いていること、Dock アイコンの文字がタイルの外に出ないこと。テキストは OCR で読みません。小さい文字では誤って成功し、一度はパネルのキャプチャをフローティングウィンドウのものとして扱いました。スクリーンショットは目で見るために残します。どれかが失敗すると非ゼロの終了コードを返します。

`scripts/verify-languages.sh` は同じ撮影とインクの方法で、表示言語ごとに実際のアプリを一度起動します。パネルとインストール画面のインクが四辺とも 24 ポイント以上ウィンドウ端から離れていることを検証します。これで翻訳がはみ出したり端で切れたりしていないことが示せますが、訳文の読みやすさは `/tmp/quik-ui` のスクリーンショットで確認します。

ウィンドウ位置を別に検証しているのは、ウィンドウ ID による撮影が内容の正しさを示すだけで、画面に出ていることを示さないからです。初期版ではパネルが画面上端の外に出ていましたが、内容のスクリーンショットは完璧で、検査は通っていました。

アイコン検査はアプリが書き出した PNG を読みます。Dock が実際に描くのと同じ `ImageRenderer` の出力です。正方形であること、文字の画素が縁に触れないこと、文字の高さがタイルの半分以上であることを検証します。詳細モードでは測れる条件を二つ追加します。スコアとラベルの縦の隙間がタイル辺の 12% 以下であること、ラベルの下端がタイル下端から 20 ピクセル以上あること。さらにユニットテストが 100 点のアイコンを描画し、白い画素の横方向の広がりを測るので、3 桁のスコアが切り詰められると OCR なしでビルドが失敗します。

## 計測の限界

Quik が測るのはシステムの競合であり、他のアプリの UI フレーム時間ではありません。macOS には、あるプロセスが別のプロセスのメインスレッドの停止を外部から読む公開インターフェースがありません。

そのためパネルが示すのは「誰がリソースを使っているか」と「システムが対話スレッドを時間どおりにスケジュールできるか」であり、「このアプリが固まった」ではありません。CPU が飽和していても応答遅延が正常なら、Quik は「やや重い」と報告し、「止まっている」とは報告しません。メモリプレッシャーが critical、または温度が critical の場合は例外で、カーネルがすでにアプリを凍結したりクロックを下げたりしているため、直接「止まっている」と報告します。

負荷から状態への対応と判定曲線の根拠は `docs/metric-validation.md` にあります。

## 構成

```
Sources/Core/       判定エンジン、差分、体験プローブ、履歴、エージェント用ステータスファイル
Sources/Probe/      mach、sysctl、libproc、IOKit のサンプリングと C ブリッジ
Sources/UI/         メニューバー、パネル、アクション、プレビュー状態
Sources/CLI/        quik コマンドラインツール
Sources/Resources/  アプリ同梱の AI アシスタント用スキルファイル
Sources/App/        エントリポイント
Tests/              ユニットテスト
scripts/            ビルド、UI 検査、計測実験
docs/               意思決定ログと計測の検証
```
